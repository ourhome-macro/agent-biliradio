# Golden Set 扩充与评测可信性修复

日期：2026-10-21。完成初版 CI 后，进一步审阅 RequestSpec、推荐策略、路由、记忆检索和 trace 脱敏实现。

## 首先修复评测自证

原排序夹具从 `expected.forbiddenIds` 读取候选黑名单，再用替代策略过滤候选。这样“禁止项不出现”并不能证明真实策略正确。

现改为直接使用真实 RecommendationPolicy：数量、来源和用户跳过反馈属于 input；expected 只计算判定结果。保留原案例 ID 与阈值，为既有排序样本补齐真实来源，并把跳过状态显式放入输入。没有降低 `gates.v1.json` 门槛，也没有覆盖历史基线快照。

另加两个反例：将实际会被选中的候选标成禁止，必须判失败；同时禁用策略的两层跳过反馈防线，原业务案例必须失败。NaN / Infinity 指标也不能靠浮点比较规则被误判为达标。

## 新增 13 个固定案例

| 范围 | 新增覆盖 |
| --- | --- |
| 请求解释 | 排除英文但要求华语女声；韩语女声唱跳范围并排除说唱 |
| 场景 | 新的情绪方向清空旧语言 / 流派；明确“再来一批”继承舞台范围 |
| 路由 | 讨论推荐算法不能自动启动找歌 |
| Trace | 嵌套 Cookie / refresh token 脱敏，同时保留数值 token 用量 |
| DAG / 资源 | 拒绝缺失依赖；视频 ID 与 trackId 不匹配 |
| 记忆 | 同租户不同用户隔离；exact session 不能读取其他会话 |
| 排序 | 跳过录音、近期已推荐轨道、语言与流派同时约束；高分不能越过过滤 |

数据位于 `recommend-radio/evals/golden/regression.v1.jsonl`，预期由业务不变量给出，没有按实际输出自动生成答案。原始 27 个案例继续保留，总计 40 个。

`manifest.v1.json` 固定必需案例 ID 和数量下限；删除新增案例也会失败。加载时要求 input / expected 对象和合法 layer，不能用无预期的空案例增加数量。

## 暴露并修复的问题

取消夹具替代过滤并加入新样本后，首次得到 38/40：

1. 高分但 BVID 格式无效的候选会进入推荐结果。现在在 RecommendationEngine 的 serving 边界先拒绝无效 BVID，再执行实际策略。
2. “讲讲推荐算法如何工作”会从规则路由的兜底分支触发推荐搜索。现在讨论短语在该分支也保持非执行语义。

两个行为修复后 Golden 为 40/40，所有阈值通过。含修复的统一 PR 命令完整通过（297 个 Python 案例）；补充清单守卫后的门禁 / Golden 专项 14/14 通过。

当前汇总 NDCG@8=0.9684、Hit@8=1.0、diversity=0.7959。因为样本组成和夹具已变化，这些值是新套件结果，不能与旧 27 案例的数值直接比较为推荐质量提升。

## 验证边界

本轮做的是源码审阅和可执行确定性验证，没有调用真实 LLM、B 站账号或浏览器；BVID 格式检查也不代表资源线上可播放。真实模型、界面和端到端效果仍需独立验收。命令和 CI 分层见 [质量门禁](quality.md)。
