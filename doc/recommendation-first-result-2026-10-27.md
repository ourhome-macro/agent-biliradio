# 对话推荐首批结果延迟优化

日期：2026-10-27。状态：实现与隔离验证完成，未部署。受控模型、真实 Vue/HTTP/SSE/MySQL 的 20 次修改后请求全部低于 3 秒；该结果不代表生产高并发或真实模型供应商 SLA。返回 202、空卡片和进度提示均不算达标。

## 本轮改动

- 对话选曲、对话补货入队、对话侧画像展示读取已提交的记忆画像，不再每次等待模型合成画像。明确画像分析入口仍保留模型能力。
- 选曲完成后，卡片、assistant turn 和首批 session 事件／SSE Outbox 同事务写入。状态为 running，不提前把任务标为 done；提交后再完成可选分析。断线可以从事件日志或持久会话恢复。
- Discovery 的候选文本向量改为独立 content_embedding 持久任务，最多 64 条，经 media 通道消费，保留词法 MMR。向量请求失败必须触发任务重试，不能以成功确认。
- 向量请求结束后锁定并重新检查源元数据；过期结果不覆盖变更后的内容，后台任务重试时重新读取当前数据。
- 查询向量编码与离线任务分离：在线每次 HTTP 超时参数为 250ms，离线批量保持原预算；不可用时沿用已有词法 MMR，并在 trace 中记录实际编码耗时与回退原因。这不是整个推荐请求的硬截止保证。
- 语义路由单独限制为默认 1.2 秒、最多 400 输出 tokens，超时参数可通过 `RECOMMEND_DIALOGUE_ROUTER_TIMEOUT_SECONDS` 配置并限制在 0.1～2 秒。超时明确报错，不将模糊意图静默改成规则推荐，也不计入推荐成功。
- 新 SSE 连接先取得游标，再读取当前用户的只读会话快照，解决快速完成任务先于 EventSource 连接的丢首卡窗口；快照不触发模型，不创建会话，未知会话返回 404。
- 修复 MySQL 严格模式下关键词归因 `DISTINCT + ORDER BY` 非选出字段的错误，按关键词／family 分组后用最近发现时间排序；不放宽 MySQL 严格模式。

明确的推荐请求原已具备高置信规则路由，本轮保留；复杂语义仍可能调用模型理解，未通过缩短等待后放宽条件来制造速度提升。严格请求库存不足时仍显示真实补货状态。卡片／事件的原子性限于业务库，Agent 工具日志仍使用已有跨库恢复与对账机制，不声称跨库事务。

## 浏览器对照结果

请求固定为“推荐几首音乐”，独立准入池 256 条，真实生产筛选／排序、任务提交、业务事件持久化、内置 ASGI SSE 和当前 Vue 页面。通过 Playwright Chromium 测量点击发送到新卡包含 8 条候选、至少一条进入视口并经历下一帧的时间。

| 数据库／分组 | 样本数／组 | 修改前首卡 P95 秒 | 修改后首卡 P95 秒 |
| --- | ---: | ---: | ---: |
| SQLite／冷画像投影缓存 | 10 | 5.669 | 1.720 |
| SQLite／热画像投影缓存 | 10 | 2.514 | 1.697 |
| 原生 MySQL／冷画像投影缓存 | 10 | 5.964 | 2.639 |
| 原生 MySQL／热画像投影缓存 | 10 | 3.122 | 2.224 |

MySQL 修改后 20 次合并计算 P95 为 **2.224 秒**，最大 **2.639 秒**；SQLite 合并 P95 为 **1.697 秒**，最大 **1.720 秒**。百分位按 nearest rank 计算，不平均各组 P95。

冷组只清空画像合成缓存，不代表重启服务器、清空数据库页缓存或全冷启动。画像模型是受控的 3.2 秒延迟，前后使用同一空画像输出；20 次实验中对照侧有 10 次冷请求模型调用，另有一次页面初始化调用，修改侧为 0。语义路由在对照和修改组均关闭，走原有明确意图路径；复杂意图／真实供应商延迟没有被此实验验证。

对照使用 `fcaf202c92e967671638ede54241e5be20b00951` 的四个对话／推荐／SSE 模块，其余共用当前兼容层，包括 MySQL 归因 SQL 修复。因此这是对话关键路径对照，不能说原历史提交未经修复就能运行该 MySQL 测试。固定 A 后 B、顺序请求、小样本，不提供线上容量或置信区间结论。

最后另做一组 SQLite 复核：首卡 5.636→1.467 秒（冷）、2.043→1.047 秒（热），两侧各 2 个任务最终均 completed。该单组未混入上述 P95。

原始记录及哈希见[结果快照](recommendation-first-result-2026-10-27.json)。样本记录 `receivedMs` 为浏览器收到 session 事件时间，`visibleMs` 为实际 Vue 卡片进入视口后的时间；不是只测后端返回。播放预热的外部请求在夹具中被禁止，本轮不验证 B 站播放解析或首帧。

## 正确性与运行边界

- 独立原生 MySQL：15 项通过，包括卡片／事件回滚、本地与兼容远程 SSE Outbox、重放幂等、模型失败重试、过期向量拒绝、严格请求不足一页、路由超时、新连接快照与空卡不计首推。
- `quality.py pr`：378 passed / 60 deselected、Golden 40/40、前端 10 项及类型检查／构建通过。60 项未选择的集成测试不计为本轮通过；完整 main 未执行。
- 性能与功能测试分开运行。使用独立数据目录和原生 MySQL，仅存储无实际权限的夹具 Key，不读取业务数据库或私有账号，不调用真实模型 API。
- 使用生产任务提交和执行代码，夹具 SQL worker 每 10ms 轮询；未包含真实 Kafka 排队、OIDC 登录成本、外部补货或完整冷启动。生产三秒目标仍须在实际队列负载与模型配置下验收。
- 向量 MMR 的 250ms 预算可能增加词法重排比例，应通过 trace 观察并复核推荐质量；Golden 验证业务不变量，不代表线上 CTR／完播率不变。

本轮无新增数据库迁移。上线时须一起更新 Web、jobs/events 和 media workers；新 `content_embedding` 任务依赖更新后的 media 消费者。任务失败仍按持久化任务机制重试，不能只更新 Web 后忽略未知任务类型。本轮没有更新现有运行容器或新增自动发布流程。
